## Outstanding security issues
1. **High** — Public GitHub repository contains entire website/admin implementation and historical backup HTML. Review repository visibility and any historical secrets before making private or rotating credentials.
2. **High** — `get_webinar_access(email)` grants Zoom link to anyone who knows a registered email, by design. Require verified email OTP or authenticated session for private webinar access.
3. **High** — `get_webinar_review_result(email)` returns participant review details by email alone. Add verified participant identity.
4. **High** — `webinar-registration` function in repository uses privileged service key, public CORS, and only an email registration lookup before Zoom registration. Confirm whether deployed, then add authentication/rate limiting and avoid leaking internal errors.
5. **Medium** — AI access is cached in localStorage; treat it as UI state only, not a security boundary. Server-side checks must guard all sensitive content.
6. **Medium** — Review all public SECURITY DEFINER RPC functions, especially user-enumeration and tracking endpoints. Do not blindly revoke: registration and public tracking require anonymous access.
7. **Medium** — Public profile policy was removed. Test any public community/leaderboard screens that expected unauthenticated profile joins.
8. **Medium** — Supabase performance advisor reported 5 unindexed foreign keys, 12 RLS initialization-plan warnings and overlapping permissive policies.
9. **Medium** — CDN dependencies `@supabase/supabase-js@2` are not pinned to an exact version.
10. **Medium** — Audit dynamic `innerHTML` rendering in both admin dashboards for unescaped user-provided values and potential XSS.
11. **Medium** — Old `admin-panel.html` and newer `webinar-admin.html` both exist; review whether legacy admin should remain publicly routable.
12. **Low** — `vercel.json` globally sets no-store; review asset caching/performance and whether the live host is Vercel or another platform.
